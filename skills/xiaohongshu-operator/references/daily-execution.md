# 每日执行与续接

本流程读取已有年度/月度/周度排期，不自动换题，也不把“每日内容规划”当作已启用定时任务。

## 启用前确定一次

沿用已有回答，只补缺项：项目/栏目与本地计划路径、真实目标账号、每天时间及 `Asia/Shanghai` 等时区、每天篇数、开始日期、运行模式、是否包含新内容生成及其预算。缺少关键设置先完成接入与成品准备，不猜发布时间或打开自动发布。

三种模式：

- `prepare_only`：接好能力，无每日任务。
- `daily_prepare`：到点读取下一个计划项，在授权范围内完成成品，待用户确认发布。
- `publish_reviewed`：按已授权的频率和范围发布已审核且具有相应发布授权的成品；空队列报告缺稿，不自行生成或补发多篇。

用户可以明确授权连续自动制作并发布；此时记录系列范围、素材来源、审核标准、数量、生成预算、有效期限和发布权限，复用授权而非每天重复询问。仅同意安装能力不构成这项授权。

## 定时机制

在 Codex 中使用可用的 `automation_update` 工具，默认当前聊天 heartbeat。先检查现有 automation 配置，更新同一目标而不是重复创建。不手写 RRULE 配置文件，不额外启动 OS 定时器或 cron。按用户明确要求才建立独立任务。保存工具返回的任务 ID、真实状态、时区和时间。工具创建成功也不等于发布已经测试成功。

若设置尚未确定，交付待启用状态和已经完成的能力，不创建假定时间的任务。已有与此任务无关或暂停的自动化保持原状。

任务提示应明确：读取哪个计划和状态；每次最多处理几篇；选用哪个模式；只继续最早适合的未完成 post_id；复用已通过素材；通过 xiaohongshu 制作、xiaohongshu-publisher 提交；共享同一个账号回执目录；遇账号失效/需要验证码/缺稿/审核未过时停止该篇并报告。状态未改变且没有可行动结果时保持安静，仅在有意义的完成、失败或需要用户操作时通知。

## 每次执行

1. 读取当前日期、账号、月/周计划、实际成品和发布回执，确认不是重复运行；错过日期的项目先顺延，不连发补欠。
2. 选取授权数量内的下一项。已经提交、预约、已发布或结果不明的项不再次发送；预约项未到点不标记已发布。
3. 缺成品转 xiaohongshu；有成品就检查版本与审核。内置出图若只返回内联图且需要后续保存/审核，保留待续接状态，不能冒充全自动生产完成。
4. 待确认模式交付可审核成品；自动发布模式检查现有发布授权，交给 xiaohongshu-publisher 执行。登录和身份校验只处理目标账号。
5. 根据服务回执及平台观察分别记录“已接受提交 / 已预约 / 已观察到发布”；未知结果先查平台再决定后续。数据复盘仅使用实际可读指标。

公开定时发布有两个时间：每日任务唤醒时间与平台预约发布时间。直接到点发布时不传已过期的 `schedule_at`；提前提交平台预约时遵循服务当前允许的窗口。两种方式择一，避免同一篇既被预约又被每日任务再发一次。

依赖清单：实际运行主机/应用可用、服务健康、账号登录有效、审核成品可读、明确的持续授权。离线后的任务执行以工具实际行为为准，不承诺关机期间自动运行。发布前不通过删除回执、换 post_id、换传输方式来绕开重复保护。
