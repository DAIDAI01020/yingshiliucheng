# Stage Handoff Contract

Use when several film-workflow skills contribute to one deliverable. This is an internal cooperation contract, not a new mandatory packet, approval gate, or reason to run extra skills. Standalone tasks remain standalone.

## Start From Available Work

Inherit the current task, execution intent, relevant accepted decisions, route, platform/model, output format, and user delta. Reuse complete upstream work; only reopen decisions contradicted by the current request or supported failure evidence. An approved script does not need a new concept pitch; a complete prompt does not need semantic reconstruction.

Distinguish known facts, working assumptions, and decisions needing approval. Brand claims, product specifications, source timecodes, reference provenance, production status, and client approval must have evidence. A reasonable creative assumption may support a draft but cannot be relabeled as an approved production fact.

## One Current Owner

The owner supplies its actual creative or technical contribution, not a list of skill names. Supporters add only a needed missing input. Skills are procedures used in the current chat; listing a specialist does not mean another agent or chat was created.

Pass only what the next owner needs, reusing existing packets or artifact sections:

| Information | Meaning |
| --- | --- |
| Task and output | Exact deliverable, scope, format, relevant shot/scene IDs |
| Source and status | Source path/version or conversation artifact; draft, reviewed, or approved with its basis |
| Decisions and preservation | Concrete contribution, applicable locks, reference roles, permitted changes |
| Open dependencies | Exact missing decision, current owner, and the work that is waiting on it |
| Completion evidence | Actual artifact/path, checks performed, remaining limitations |

Do not demand empty fields or serialize a packet for prompt-only work. In managed work, use existing state schemas and owners; do not introduce a competing registry or rename IDs during handoff.

## Dependency Order

Drafting can precede production approval. A scene map and shot plan may be drafted from the script and reference direction; the shot audit checks that plan; the style bible consolidates relevant decisions; the style lock freezes the approved result. Do not require a completed downstream lock or audit merely to create the upstream material it depends on.

Hold dependent generation until applicable gates pass. Missing data already present in accepted material can be restored with provenance. Missing creative decisions go to their owner for a concrete proposal. Continue independent authorized work; do not pass an unchanged blocker in a circle.

## Evidence And Revisions

Keep these distinctions: draft is not approved; submitted is not generated; generated is not QC passed; QC passed is not client-selected; a reference or intended path is not a saved output. Use the vocabulary of the existing registry when writing state. Do not mark a creative proposal approved merely because its file exists or a technical check passes.

For a revision, identify the source version, requested delta, preserved decisions, and affected dependents. Keep stable shot/asset IDs and trace versions. Repeated artifacts justify investigation, not automatic global style changes. A proposed fix is not a successful fix until its result has been inspected.

## Deliver The Requested Form

| Request | Completion |
| --- | --- |
| Script, concept, prompt, or outline | Finished usable content at the requested depth |
| PPTX, spreadsheet, document, or PDF | Real saved file, using the available artifact skill/tool, with its required inspection |
| Generated image/video | Actual returned media or verified local output; report partial success per requested item |
| Review | Evidence-based findings for inspected material; identify uninspected dimensions |
| Delivery package | Selected approved versions, verified files, required formats, and a useful delivery index |

An outline is not a finished PPTX; a contact sheet is not full video playback; an image board is not the individual images unless requested. Do not fabricate paths, links, thumbnails, timing, or generated results. Apply built-in image response rules when returning its native result.

Show the artifact and material decisions to the user. Internal routing, repeated source packets, and full production history remain internal unless diagnostics are requested. Complete the requested scope without inventing a new stage after it is done.
