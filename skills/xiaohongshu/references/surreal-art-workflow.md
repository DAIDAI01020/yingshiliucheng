# 日常空间里的神秘超现实：每日艺术图分支

## 使用边界与创作基线

本文件负责 `surreal_art` 分支的制作流程，长期创意与审美标准见 [art-direction-standards.md](art-direction-standards.md)。总控只选路，xiaohongshu-operator 负责账号定位、选题策略与数据复盘，小红书制作技能负责单篇画面、成稿和发布衔接，各专业技能提供自己的实际判断。既有素材和有效审核可以复用，记录版本，不每天从头搭建整条流程。

## Branch Isolation

- 只有明确的小红书艺术栏目任务，或当前项目/对话已确立的每日艺术图、《日常之外》续作，才启用本分支。单独的“神秘感、超现实、出图、审核、每天做图”不构成进入条件。
- 用户当前明确的交付物和已有项目/栏目状态优先。短剧、TVC、品牌、KV、海报、故事板等需求继续由原负责人处理；即使要求“超现实一点”或“神秘一些”，也只改变该项目的指定视觉属性。
- 原小红书影视场景设计 / 一日一镜继续使用 `film_diary`，不因采用超现实表现就迁移栏目。新小红书任务未指定内容方向时，先继承已有栏目；没有上下文时保持未选方向，只有该选择阻碍具体制作才询问。
- 把已有广告、KV、短剧图上传小红书，只调用发布素材整理与上传功能，保留源项目根目录、素材、风格、审核、比例和平台；不强制重做三张图或变成神秘超现实。
- 这里的三张图、3:4、自然空间、悬念线索、艺术审核与选题轮换只作用于本栏目的任务；不得写入共享生成/提示词/审核技能作为全局默认，不得修改其他项目的锁和状态。
- 跨栏目只复用技能能力。风格、参考、授权、选中版本和账号必须来自当前项目或用户明确允许的来源；栏目记录绑定现有 `project_root`、`series` 和 `post_id`，不能靠最近使用过的文件推断。

## 本栏目基线

用户已确认的方向：熟悉的生活空间出现超现实变化，可以有神秘感；长期沿用这种方向。用户要求出图、适用技能审核和后续上传能力。栏目名《日常之外》、3:4比例、每篇三张是可调整的制作默认，不冒充已经批准的账号名称或首图样式。

- 核心：从熟悉的生活经验出发，以具体的形态、空间、色彩或物件关系构成有想象力的画面。“日常空间加异常”只是题目起点，不是每篇的完成公式。
- 情绪可在温柔、安静、好奇、孤独、梦境和轻微不安之间变化；神秘感不自动升级成血腥、怪物或恐怖惊吓。
- 按当篇表达选择摄影、装置、绘画、拼贴或混合媒介；已选定的风格范围优先。每种媒介写清实际表现机制，不以“高级艺术感”代替设计，不擅自变更用户锁定的媒介。
- 光线与色彩保持系列气质，但不把全账号锁成黑夜或青绿色。乳白晨雾、褪色粉墙、暖色日光也可营造神秘。
- 审核保留刻意的异常：室内海水、森林洗衣房、通往麦田的衣柜都可以成立。检查异常之外的空间、物体关系和材质是否自洽。
- 同组可以围绕同一空间展开，也可以按明确的视觉命题组织关联作品。前者保持空间连续性，后者保持选定的形态、色彩或观念联系；不得混成三个无关点子。全栏目不锁成同一房间、配色、极简或繁复风格。

## 选题与每日简报

本栏目按年度章节 → 月度日历 → 周度制作队列 → 每日post_id推进。下面的视觉题库只作备选；已有日历时优先制作计划中尚未完成的条目，不随机挑一条发布。用户可见交付重点是长期安排和具体画面，无需每天解释“为什么发”。

运营策略与选题优先级由 [小红书运营](../../xiaohongshu-operator/SKILL.md) 决定并交付 operations_brief；本节提供视觉题库和制作转译。已有明确选题/用户brief直接制作，不反复重做账号策划。下列题目是创作候选，不代表经过账号数据验证的运营排期。

先查已有项目中的选题、素材与发布记录，避免把已完成的一篇再次生成或上传。同一母题可以延伸，但写清新的空间、异常或情绪差异。

可轮换：自然进入室内、人工空间被植物接管、门窗连接未知空间、天气发生在房间里、灯光与时间异常、日常尺度改变。周末可以继续艺术主题；合集和拆解按实际内容需要安排。

以下仅为母题草案，必须经过艺术发展才能成为制作方案；已有项目修订优先，不回退至已被用户否定的旧画面，不视为批量执行授权：

| 题目 | 主异常与线索 |
| --- | --- |
| 把海搬进房间 | 旧房间铺着浅水，木椅脚有湿痕，白纱倒映在水里 |
| 末班车开进了花园 | 植物从公交车座位间生长，停靠处有一盏亮灯 |
| 森林深处，有一间亮着灯的洗衣房 | 湿雾包围小店，一台机器正在转，门外留着湿脚印 |
| 退潮后，海上出现了一扇门 | 浅海立着旧木门，门缝暖光映在水上 |
| 整栋楼，只有这一扇窗是白天 | 夜色旧公寓里，一扇窗透出明亮日光 |
| 衣柜后面是麦田 | 旧卧室的柜门半开，里面的麦穗被风吹动 |
| 洗衣机里，潮汐照常发生 | 空洗衣房中，一只滚筒玻璃后出现缩小的海岸 |

每篇保存精简简报：`post_id`、主题与一句话概念、情绪、主异常、悬念线索、空间/物件、光线/配色/材质、比例、图片职责、继承的风格版本、用户新要求和授权范围。用现有项目文档保存，不另建竞争性素材数据库。

默认三张独立图片，按具体作品设计各自职责：

1. 封面：建立这一篇最有辨识度的视觉命题；景别由构图决定。
2. 延伸：改变观看关系或揭示新信息，不能只换机位凑数。
3. 余味：用呼应、缺席、局部或反转使观念继续生长；特写并非必需，每张独立观看也须成立。

全景、另一机位、细节只在适合具体作品时采用。同场景图组保留门窗、灯具、物件等实际关系；观念关联组在brief中写明连接规则。

不把三张独立图片替换成拼图。默认无图中文字、无虚构logo，文案另存。默认3:4；平台实际输出比例有偏差时验证并按构图修正，不假称尺寸完全符合。需要更换机位时允许透视、遮挡和取景改变，不能锁死屏幕坐标。

## 生产与适用审核

长期栏目请求成套出图、审核、留档和上传素材时，使用总控的 `formal_managed`、`main_line:other`、`workflow_mode:image`、`qc_mode:formal`。摄影式空间图使用 `deliverable_profile:storyboard_frame`；插画或抽象图按实际媒介选profile。想法讨论、提示词或单图试效果仍走相应轻量模式。

| 阶段 | 实际负责人 | 必须产生的结果 / 通过条件 |
| --- | --- | --- |
| 目录与继承 | project-folder-director → project-state-manager | 复用/确定项目根目录、当篇ID、输出位置、已完成工作与现有授权 |
| 运营简报 | xiaohongshu-operator（复用已有，按缺失项补） | 年/月章节、post_id、当篇命题、近期重复风险和制作顺序；不要求每天解释为什么发或提供增长数据 |
| 创意与图组设计 | xiaohongshu | 具体想象、画面组织、媒介表现、情绪、三张各自的信息；按长期艺术标准完成前置自检，不以题目或形容词代替方案 |
| 参考与审美 | style-reference-director → reference-visual-library / reference-aesthetic-director，按缺失内容调用 | 可执行的空间、光线、色彩、材质机制；复用足够明确的已定系统，新增参考保留真实来源 |
| 场景与镜头 | scene-style-map-director；shot-language-auditor 在多机位/叙事图组适用 | 每篇空间与异常锚点、机位变化、画面信息递进；单图不强制景别审查 |
| 风格整合与冻结 | style-bible-director（需要整合时）→ project-style-lock | 锁住已确认的方向、保持项、可变项与刻意超现实项，保留来源；不虚构首图已获用户选定 |
| 提示词 | frame-vision-director → prompt-platform-auditor | 每张完整独立语义源与目标平台审查；通过后形成适用的 generation-ready 记录 |
| 实际生成 | 所选平台的执行技能 | 真实返回的图片/任务ID；保存原始结果并核实文件，成功图不重复提交 |
| 出图审核 | image-qc-director | 实际查看图片与参考，结合技术证据，逐张和整组给出结论、版本及问题归因 |
| 修订与复审 | revision-director → 对应提示词/平台/上游负责人 → 原执行平台 → image-qc-director | 只改失败项，修后重新查看；未检查的新版本不能继承旧版通过状态 |
| 素材与文案 | asset-librarian / project-state-manager；xiaohongshu | 可用版本、顺序、文件、审核证据、标题正文标签和实际发布状态 |
| 运营包装检查 | xiaohongshu-operator（成套运营范围适用） | 封面/标题/图组兑现同一承诺、系列辨识度和受众价值；有具体问题才修正，不等于流量保证 |

“各个skill审核”指适用专业环节都有实际结果，不让每个已安装技能审每张图。无人空间不强制角色小传；艺术图不强制品牌卖点、LED安全区、视频时长/音频或短剧开篇钩子。需要人物连续性、产品结构或商业版本时，才接入相应负责人。

已有明确审美机制可以直接复用；需要参考研究时先选库再转译，不堆导演/电影名字，不凭空声称看过参考。用户提供参考图时按实际角色使用 reference-image-style-matcher，不把身份/结构参考误当作风格迁移。

### 风格与同组连续性

风格锁区分：

- **系列基线**：日常空间、主异常与悬念关系、材质与光影质感、禁止的偏离。
- **单篇锚点**：空间布局、物件身份位置、时间光源、异常规则（例如水位/植物生长范围）、色彩与材质。
- **单图变化**：机位、景别、取景、对焦与显露的线索。

如用户已授权按当前方向自主完成一套，记录该授权作为执行依据，不重复询问无关细节。用户仅确认风格方向不等于已批准尚未见到的首图；将视觉样本选定和审核可用分开记录。需要锚图指导后续时，先生成封面并完成适用审核，继承其可用空间关系生成其余图片。

### 图片审核的判据

1. **主题和情绪**：无需依赖标题解释也能感受到作品的观看张力；含蓄不等于信息缺失，不把“解释不通”的创意本身打回。
2. **视觉完成度与想象力**：检查主形与背景、疏密、色彩关系、材质表达和视觉重心的具体效果；比较近期作品，不能只换道具重复旧构图。艺术性判断给出画面证据，不以漂亮、写实、分辨率或评分代替。
3. **自洽与连续性**：按当篇选定的空间或观念连接规则审核。摄影式空间检查物件、光源与倒影；绘画/拼贴检查边缘、平面、笔触和层次的一致表达，保留刻意的异常。
4. **图片技术与平台适配**：实际可解码文件、比例分辨率、封面裁切、杂字水印、明显生成瑕疵；有手脸/产品时检查相应结构。
5. **整组信息**：三张各自成立又有联系，观看关系或情绪有所推进；不能用无意义特写或近似重复补数量。

每项保留 `owner`、`status: passed / needs_fix / pending / not_applicable`、`source_version`、`evidence`、`finding`、`next_action`；存进现有当篇审核文档并链接素材ID，不能据此另造项目状态枚举。`not_applicable` 写明原因。

最终采用 image-qc-director 的统一结论：`可用 / 可小修 / 定向重出 / 提示词需重写 / 前置导演判断错误`。上传候选必须已完成适用检查并为“可用”；“可小修”先完成必要修复和复审，或记录用户明确接受的具体非阻断缺陷，不能静默算通过。

保留每次源图与新版本。审美修订默认每张最多两轮针对性修复，平台执行技能有更严格限制时从严；收费重试遵守已有授权和执行技能。达到限制、出现费用/服务不确定或问题指向前置判断时，保留结果并报告具体原因，不无限重出，不因失败自动换平台。

### 内置出图的阶段衔接

遵循 builtin-imagegen-director 的原生图片回复规则。生成回复以图片结束；审核、保存和发布包在独立审核阶段继续，不能在图片后追加虚构的审核通过。开始前说明必要的阶段边界并保存下一步任务；现有环境不能自动继续时，准确标记“已出图，待审核/捕获”，用户说“继续”即可续接，不要求重述brief或重出成功图。

若工具只返回内联图，能看图则可记录视觉审核，但本地文件仍为待捕获，不能假造路径或直接宣称可上传。使用工具实际提供的保存/导出能力；没有可用能力时说明只缺本地捕获，保留当前平台。

## 发布素材包与存放

由目录负责人确定根目录，素材不得混进工作流源码或skills目录。沿用项目现有宽目录，不另造深层工程：

- `docs/`：栏目基线、选题、当篇简报、标题正文标签。
- `prompts/`：每张词、参考角色、平台审查与执行记录。
- `images/`：真实生成原图和修订版本。
- `review/`：逐项审核、整组对比、修订与复审证据。
- `delivery/`：明确选出的发布图片与当篇发布素材包。

建议文件标识：`{post_id}_01-cover_v001`、`{post_id}_02-view_v001`、`{post_id}_03-clue_v001`，扩展名与实际文件一致。不覆盖旧版，不用伪造路径补齐缺图。发布包链接现有 asset-index 中的素材ID和版本，附每个实际文件的校验标识。

发布包至少包含：当篇ID、主题、图片顺序及实际文件、封面、标题、正文、相关标签、AI创作说明、审核结论链接、阻断项、已授权动作、目标账号（需要上传时）、草稿/发布的实际结果。包内变更图像、顺序、文字或账号后重新核对受影响部分；不要挪用旧版本发布授权。

文案默认80—150字，可随主题调整：一句引人好奇的开头，加一两句创作感受。留出想象空间，不替观众解释全部谜底。只用相关标签，明确是AI视觉创作，不声称真实拍摄/真实地点/真实客户项目。平台字数、标签数、图片和披露要求以执行时的页面/官方说明为准，不硬编码为永久规则。

发布后的实际帖子ID和版本可交给 xiaohongshu-operator，在用户要求复盘或已授权的运营周期内分析真实反馈并更新后续选题；没有监控/提醒请求，不自动创建定时任务或承诺稍后主动跟进。

## 上传与发布闭环

沿用 SKILL.md 中唯一的上传授权规则。用户说“到时候帮我上传”表示建立能力和后续意图，当前维护任务不进入账号；后续明确“上传今天这套”即可准备真实页面，无需重复询问已授权的上传动作。

上传前逐一确认：素材齐全、文件与审核版本一致、所有阻断项解决、文案已成稿、目标账号正确。缺图、未检、明显失败不得被写成“审核通过”。

实际上传完成后复核缩略图顺序、封面裁切、标题正文标签与可见AI标识，保留真实预览/草稿证据。仅在最终发布未获授权时，展示可审阅结果后请求该动作；已有覆盖该账号与版本的明确发布授权则直接执行。未知提交结果先查询，防止重复帖子。

没有生成、审核、上传或发布的实际证据，就报告对应阶段待完成。保存这条流程不表示已开通定时任务，也不承诺后台每天自动发帖。
